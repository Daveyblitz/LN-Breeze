This guide walks through a complete Lightning payment integration. Each step explains not just what to call, but why it matters and what breaks if you skip it.

The examples use JavaScript throughout. Equivalent Python snippets are included where the logic differs meaningfully.

---

## Step 1 — Get your API key

Before you can create invoices, you need an API key tied to an LNbits wallet. If you already have one, skip ahead. If not:

```js
const res = await fetch("https://ln-breeze.vercel.app/api/v1/wallets", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ walletName: "My Shop" }),
});
const { walletId, invoiceKey, lnbitsUrl } = await res.json();

const registerRes = await fetch("https://ln-breeze.vercel.app/api/v1/auth/register", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ lnbitsUrl, invoiceKey, walletId }),
});
const { apiKey } = await registerRes.json();
```

Store that `apiKey` in an environment variable. It does not expire and does not get regenerated automatically — treat it like a password.

## Step 2 — Create the invoice

When your customer is ready to pay, create an invoice for the exact amount. Do this on your server, not in client-side code — your API key must stay off the browser.

```js
async function createInvoice(amount, description) {
  const res = await fetch("https://ln-breeze.vercel.app/api/v1/invoices", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.LN_BREEZE_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ amount, description }),
  });

  if (!res.ok) {
    const { error } = await res.json();
    throw new Error(error);
  }

  return res.json();
}

const invoice = await createInvoice(1000, "Order #1042 — 2x Coffee");
// invoice.paymentRequest  → the BOLT11 string to show as a QR code
// invoice.paymentHash     → save this, you need it to detect payment
// invoice.expiresAt       → 10 minutes from now
```

The `description` is included inside the BOLT11 invoice. Your customer will see it in their wallet before they confirm the payment — make it clear and specific.

## Step 3 — Show the QR code

Send `paymentRequest` to your frontend. Encode it as a QR code using any QR library. The customer scans it with any Lightning wallet — Phoenix, Wallet of Satoshi, BlueWallet, Zeus, and dozens of others all speak BOLT11.

Also display the raw `paymentRequest` string alongside the QR code with a copy button. Users on desktop cannot scan a QR code from their own screen, so the copy option is not optional — it is how desktop payments work.

```js
// React example using qrcode.react
import { QRCodeSVG } from "qrcode.react";

<QRCodeSVG value={invoice.paymentRequest} size={256} />
<button onClick={() => navigator.clipboard.writeText(invoice.paymentRequest)}>
  Copy invoice
</button>
```

## Step 4 — Poll for payment

Once the QR code is on screen, start checking whether it has been paid. Poll every 3 seconds until `paid` comes back `true` or the invoice expires.

```js
async function waitForPayment(paymentHash, expiresAt, onPaid, onExpired) {
  const expiry = new Date(expiresAt).getTime();

  const poll = setInterval(async () => {
    if (Date.now() > expiry) {
      clearInterval(poll);
      onExpired();
      return;
    }

    try {
      const res = await fetch(
        `https://ln-breeze.vercel.app/api/v1/invoices/${paymentHash}`,
        { headers: { Authorization: `Bearer ${process.env.LN_BREEZE_API_KEY}` } }
      );
      const { paid } = await res.json();

      if (paid) {
        clearInterval(poll);
        onPaid();
      }
    } catch {
      // Network hiccup — keep polling on next interval
    }
  }, 3000);

  return () => clearInterval(poll);
}

const cancel = await waitForPayment(
  invoice.paymentHash,
  invoice.expiresAt,
  () => fulfillOrder(),
  () => showExpiredMessage(),
);

// Cancel if the user navigates away before paying
window.addEventListener("beforeunload", cancel);
```

Stop polling the moment `paid: true` arrives. The payment is final — Lightning payments cannot be reversed or disputed. You can safely fulfil the order, unlock the download, or confirm the booking without waiting for any further confirmation.

## Step 5 — Handle expiry

Invoices expire 10 minutes after creation. If the customer has not paid by then, `paid` will remain `false` permanently for that hash — no amount of polling will change it.

When expiry hits, stop polling and give the customer a clear path forward:

```js
function showExpiredMessage() {
  // Do not leave the customer on a dead QR code
  document.getElementById("status").textContent =
    "This invoice has expired. Generate a new one to continue.";

  document.getElementById("retry-btn").style.display = "block";
}

document.getElementById("retry-btn").addEventListener("click", async () => {
  // Create a fresh invoice and show the new QR code
  const newInvoice = await createInvoice(1000, "Order #1042 — retry");
  updateQRCode(newInvoice.paymentRequest);
  waitForPayment(newInvoice.paymentHash, newInvoice.expiresAt, fulfillOrder, showExpiredMessage);
});
```

A 10-minute window is generous for most payments. If a customer has not paid after 10 minutes, they have usually walked away. The retry flow handles the rare case where they were slow.

## Full integration — Python (Flask)

A complete server-side implementation for a Python backend:

```python
from flask import Flask, jsonify, request
import requests, os, time
from datetime import datetime, timezone

app = Flask(__name__)

API_BASE = "https://ln-breeze.vercel.app/api/v1"
API_KEY = os.environ["LN_BREEZE_API_KEY"]

def ln_breeze(method, path, **kwargs):
    return requests.request(
        method,
        f"{API_BASE}{path}",
        headers={"Authorization": f"Bearer {API_KEY}"},
        **kwargs,
    )

# Step 1 — Create invoice endpoint
@app.route("/checkout/invoice", methods=["POST"])
def create_checkout_invoice():
    data = request.get_json()
    amount_sats = data.get("amount_sats")
    order_id = data.get("order_id")

    if not amount_sats or not order_id:
        return jsonify({"error": "amount_sats and order_id are required"}), 400

    res = ln_breeze("POST", "/invoices", json={
        "amount": amount_sats,
        "description": f"Order #{order_id}",
    })

    if not res.ok:
        return jsonify({"error": "Failed to create invoice"}), 500

    invoice = res.json()
    return jsonify({
        "paymentRequest": invoice["paymentRequest"],
        "paymentHash": invoice["paymentHash"],
        "expiresAt": invoice["expiresAt"],
    })

# Step 2 — Status endpoint (called by frontend polling)
@app.route("/checkout/status/<payment_hash>", methods=["GET"])
def check_payment_status(payment_hash):
    res = ln_breeze("GET", f"/invoices/{payment_hash}")

    if res.status_code == 404:
        return jsonify({"error": "Invoice not found"}), 404

    return jsonify(res.json())
```

## Before going live

Run through this checklist before accepting real payments:

1. **Register** — call `/api/v1/auth/register` and confirm you receive an `apiKey`
2. **Wallet check** — call `GET /api/v1/wallet` and confirm the right wallet name and balance come back
3. **Create a test invoice** — 1 sat, description `"Integration test"`
4. **Pay it** — open a second Lightning wallet, paste the `paymentRequest`, pay
5. **Confirm detection** — verify `paid: true` appears in the poll response within a few seconds
6. **Test expiry** — create an invoice, do not pay it, wait 10 minutes, confirm your UI shows the expired state correctly

If all six pass, your integration is solid. The only remaining variable is your LNbits instance's uptime — which is why self-hosting is worth considering for anything serious.
