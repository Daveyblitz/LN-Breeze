## Overview

This endpoint creates a Lightning invoice for a given amount and description. It returns a BOLT11 payment request string — the standard format used across the entire Lightning Network. Any Lightning wallet (Phoenix, Wallet of Satoshi, BlueWallet, Muun, Zeus, etc.) can pay a BOLT11 invoice.

The invoice expires 10 minutes after creation. If unpaid after that window, a new invoice must be generated. There is no way to extend a Lightning invoice's expiry.

## Request body

<ParamField body="amount" type="integer" required>
  The invoice amount in **satoshis**. Must be a positive whole number — decimals are not valid because satoshis are the smallest unit of Bitcoin on Lightning.

  To convert from other units:
  - 1 USD ≈ varies (check current rate)
  - 1 BTC = 100,000,000 satoshis
  - 1,000 sats ≈ a typical small transaction
</ParamField>

<ParamField body="description" type="string" required>
  A short description of the payment. This is included inside the BOLT11 invoice and displayed to the payer in their Lightning wallet when they scan the QR code. Keep it clear and specific — the payer sees this before confirming.

  Example: `"Order #1042 — 2x Coffee"`, `"Monthly subscription — July"`, `"Donation"`
</ParamField>

## Response

<ResponseField name="paymentRequest" type="string">
  The BOLT11 invoice string. Always starts with `lnbc` on mainnet. This is what you encode as a QR code or give to the customer to paste into their wallet.
</ResponseField>

<ResponseField name="paymentHash" type="string">
  A 64-character lowercase hex string that uniquely identifies this invoice. Save this — it is what you pass to the [status endpoint](/api-reference/invoices/status) to check whether payment has arrived.
</ResponseField>

<ResponseField name="amount" type="integer">
  The invoice amount in satoshis, echoed back for confirmation.
</ResponseField>

<ResponseField name="description" type="string">
  The invoice description, echoed back.
</ResponseField>

<ResponseField name="expiresAt" type="string">
  ISO 8601 timestamp marking when the invoice expires. Exactly 10 minutes from creation time. After this timestamp, the invoice cannot be paid and `paid` will always return `false`.
</ResponseField>

## Postman / request body

Paste this directly into Postman's **Body → raw → JSON** tab:

```json
{
  "amount": 1000,
  "description": "Payment for logo design"
}
```

Set the `Authorization` header to `Bearer YOUR_API_KEY` in Postman's **Auth → Bearer Token** tab.

## Examples

<CodeGroup>

```bash cURL
curl -X POST https://ln-breeze.vercel.app/api/v1/invoices \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 1000,
    "description": "Payment for logo design"
  }'
```

```js JavaScript
const res = await fetch("https://ln-breeze.vercel.app/api/v1/invoices", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.LN_BREEZE_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    amount: 1000,
    description: "Payment for logo design",
  }),
});

const invoice = await res.json();

// Show the QR code
renderQRCode(invoice.paymentRequest);

// Start polling for payment
pollForPayment(invoice.paymentHash);
```

```python Python
import requests, os

res = requests.post(
  "https://ln-breeze.vercel.app/api/v1/invoices",
  headers={"Authorization": f"Bearer {os.environ['LN_BREEZE_API_KEY']}"},
  json={
    "amount": 1000,
    "description": "Payment for logo design",
  },
)

invoice = res.json()
payment_hash = invoice["paymentHash"]
payment_request = invoice["paymentRequest"]
```

</CodeGroup>

## What to do after creating an invoice

1. **Show the QR code** — encode `paymentRequest` as a QR code using any library (`qrcode` in Python, `qrcode.react` in React, etc.)
2. **Store the `paymentHash`** — you will need it to check payment status
3. **Start polling** — call [GET /api/v1/invoices/:hash](/api-reference/invoices/status) every 2–3 seconds until `paid: true` or the invoice expires

## Error responses

| Status | Message | What happened |
|---|---|---|
| `401` | `Invalid or missing API key` | Bearer token is missing, expired, or invalid |
| `400` | `amount must be a positive integer (satoshis)` | Amount is missing, zero, negative, a decimal, or not a number |
| `400` | `description is required` | Description field is missing or empty |
| `500` | `Failed to create invoice` | LNbits returned an error — check that your wallet has sufficient inbound liquidity |
