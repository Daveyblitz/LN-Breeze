<Info>
  All paths on this site are relative to **`https://ln-breeze.vercel.app`**. The full URL for this endpoint is `https://ln-breeze.vercel.app/api/v1/invoices/{hash}`.
</Info>

## Overview

Once you have created an invoice and shown the QR code to your customer, you need to know the moment it gets paid. This endpoint is how you do that.

Poll it on an interval — every 2 to 3 seconds is a good balance between responsiveness and server load. The moment `paid` comes back `true`, stop polling and trigger your fulfilment logic. If the invoice expires unpaid (10 minutes after creation), `paid` will remain `false` permanently for that hash.

## Path parameters

<ParamField path="hash" type="string" required>
  The `paymentHash` returned when the invoice was created. Must be exactly 64 lowercase hexadecimal characters.

  This is validated server-side — requests with malformed hashes (wrong length, non-hex characters, path traversal attempts) are rejected before reaching LNbits.
</ParamField>

## Response

<ResponseField name="paymentHash" type="string">
  The payment hash, echoed back so you can match the response to the right invoice in your application.
</ResponseField>

<ResponseField name="paid" type="boolean">
  `true` if the invoice has been settled. `false` if it is still pending or has expired unpaid. Once `true`, it will always be `true` — Lightning payments are final.
</ResponseField>

## Postman setup

This is a GET request — no body needed. In Postman:

1. Set method to **GET**
2. URL: `https://ln-breeze.vercel.app/api/v1/invoices/PASTE_PAYMENT_HASH_HERE`
3. **Auth → Bearer Token** → paste your API key

The `paymentHash` comes from the response of `POST /api/v1/invoices`.

## Examples

<CodeGroup>

```bash cURL
curl https://ln-breeze.vercel.app/api/v1/invoices/a3f9bc2d1e4f5a6b... \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```js JavaScript
async function waitForPayment(paymentHash, apiKey, onPaid, onExpired, expiresAt) {
  const poll = setInterval(async () => {
    // Stop if the invoice has expired
    if (Date.now() > new Date(expiresAt).getTime()) {
      clearInterval(poll);
      onExpired();
      return;
    }

    const res = await fetch(
      `https://ln-breeze.vercel.app/api/v1/invoices/${paymentHash}`,
      { headers: { Authorization: `Bearer ${apiKey}` } }
    );

    const { paid } = await res.json();

    if (paid) {
      clearInterval(poll);
      onPaid();
    }
  }, 3000); // poll every 3 seconds
}
```

```python Python
import requests, time, os
from datetime import datetime, timezone

def wait_for_payment(payment_hash, expires_at, on_paid, on_expired):
    api_key = os.environ["LN_BREEZE_API_KEY"]
    expiry = datetime.fromisoformat(expires_at.replace("Z", "+00:00"))

    while datetime.now(timezone.utc) < expiry:
        res = requests.get(
            f"https://ln-breeze.vercel.app/api/v1/invoices/{payment_hash}",
            headers={"Authorization": f"Bearer {api_key}"},
        )
        if res.json().get("paid"):
            on_paid()
            return
        time.sleep(3)

    on_expired()
```

## Polling vs WebSockets

Polling this endpoint works well for most use cases. For applications that need true real-time detection (under one second), consider opening a WebSocket connection directly to your LNbits instance at `wss://your-lnbits-url/api/v1/ws/<walletId>`. LNbits emits a message the moment a payment arrives.

A robust implementation uses both: WebSocket as the primary detection channel, polling as the fallback if the WebSocket connection drops.

## Error responses

| Status | Message | What happened |
|---|---|---|
| `401` | `Invalid or missing API key` | Bearer token is missing or invalid |
| `400` | `Invalid payment hash — must be a 64-character hex string` | The hash in the URL is not a valid format |
| `404` | `Invoice not found` | No invoice with this hash exists on the connected wallet |
| `500` | `Failed to check invoice status` | LNbits returned an error |
