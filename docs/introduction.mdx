## The problem

Accepting Bitcoin payments on the web is harder than it should be. On-chain Bitcoin is slow — ten-minute confirmation times and unpredictable fees make it impractical for anything that needs to feel instant. The Lightning Network solves both problems: payments settle in seconds for fractions of a cent.

But building on Lightning directly means running a node, managing payment channels, handling liquidity, and dealing with infrastructure that assumes you are a systems engineer. Most developers just want to generate an invoice and know when it gets paid. The plumbing should not be their problem.

That is what LN-Breeze is for.

## What LN-Breeze does

LN-Breeze is a thin, secure API layer that sits between your application and [LNbits](https://lnbits.com) — an open-source Lightning wallet server. You bring your own LNbits wallet. LN-Breeze handles the API calls, secures your credentials, and gives you clean endpoints to build on.

Three things, done well:

- **Create invoices** — generate a BOLT11 Lightning invoice for any satoshi amount with a single POST request
- **Detect payment** — poll for confirmation or let your own WebSocket implementation react in real time
- **Stay secure** — your LNbits credentials never leave the server; developers authenticate with signed API keys, not raw wallet keys

## Who this is for

LN-Breeze is for developers who want to add Lightning payment support to a web app, e-commerce store, SaaS product, or point-of-sale system — without becoming Lightning infrastructure engineers in the process.

If you can make an HTTP request, you can accept Bitcoin Lightning payments.

## How the API works

```
Your app → POST /api/v1/invoices → LN-Breeze → LNbits
                                                   ↓
                                        invoice created

Customer scans QR code, pays from any Lightning wallet

Your app → GET /api/v1/invoices/:hash → LN-Breeze → LNbits
                                                        ↓
Your app ← { paid: true } ←────────────────────────────┘
```

LN-Breeze proxies calls to LNbits using your credentials — but those credentials are sealed inside a signed token. Neither your Invoice Key nor your Wallet ID is ever exposed in a browser or stored in a database.

## Before you start

You will need one thing: an LNbits wallet.

The fastest way is to go to [demo.lnbits.com](https://demo.lnbits.com), create a free wallet, and grab your **Invoice Key** and **Wallet ID** from the API Info panel. The demo instance works fine for testing and building. For production, consider self-hosting LNbits on your own node.

Once you have those two values, you can get an API key and make your first invoice call in under five minutes. Start with the [Quickstart](/quickstart).
