This guide walks you through the complete flow: getting an API key, creating an invoice, and confirming payment. By the end you will have made three real API calls and understand exactly how the pieces fit together.

## What you need before starting

An LNbits wallet. If you do not have one yet, go to [demo.lnbits.com](https://demo.lnbits.com), click **Create Account**, and open a wallet. Then find these two values under **API Info** in your wallet dashboard:

| Value | What it looks like |
|---|---|
| **Invoice Key** | A 32-character hex string — read-only access to your wallet |
| **Wallet ID** | Another 32-character hex string — identifies your specific wallet |
| **LNbits URL** | The base URL of your instance, e.g. `https://demo.lnbits.com` |

You will use these once to register. After that, everything goes through your API key.

## Step 1 — Register and get your API key

Send your LNbits credentials to the register endpoint. LN-Breeze verifies them against LNbits, then wraps them into a signed token and hands it back as your API key.

```bash
curl -X POST https://ln-breeze.vercel.app/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "lnbitsUrl": "https://demo.lnbits.com",
    "invoiceKey": "your_invoice_key_here",
    "walletId": "your_wallet_id_here"
  }'
```

You will get back something like:

```json
{
  "apiKey": "eyJhbGciOiJIUzI1NiJ9.eyJsb25...",
  "walletName": "My Wallet",
  "note": "Store this API key securely — it will not be shown again."
}
```

**Save that `apiKey`.** It is your permanent credential for this wallet. Treat it like a password — store it in an environment variable, never hardcode it, never expose it in client-side JavaScript.

## Step 2 — Create a Lightning invoice

Now use your API key to create an invoice. This generates a BOLT11 payment request that any Lightning wallet can pay.

```bash
curl -X POST https://ln-breeze.vercel.app/api/v1/invoices \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 1000,
    "description": "Payment for logo design"
  }'
```

```json
{
  "paymentRequest": "lnbc10u1pn2k3j4pp5a3f9bc...",
  "paymentHash": "a3f9bc2d1e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b",
  "amount": 1000,
  "description": "Payment for logo design",
  "expiresAt": "2026-07-10T15:30:00.000Z"
}
```

The `paymentRequest` is the string that becomes the QR code. The `paymentHash` is what you use to check whether it was paid. The invoice expires after 10 minutes.

## Step 3 — Let someone pay it

Take the `paymentRequest` string and either:
- Encode it as a QR code and show it to your customer
- Let your customer copy-paste it into any Lightning wallet (Phoenix, Wallet of Satoshi, BlueWallet, etc.)

For testing, you can open a second LNbits wallet, go to **Send**, and paste the BOLT11 string directly.

## Step 4 — Confirm payment

Poll the status endpoint until `paid` comes back `true`:

```bash
curl https://ln-breeze.vercel.app/api/v1/invoices/a3f9bc2d... \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "paymentHash": "a3f9bc2d...",
  "paid": true
}
```

In a real application you would poll this every 2–3 seconds after showing the QR code, then trigger your fulfilment flow the moment `paid` returns `true`. See the [status endpoint reference](/api-reference/invoices/status) for polling examples in JavaScript and Python.

<Note>
  The invoice expires 10 minutes after creation. If `paid` is still `false` after expiry, stop polling and generate a new invoice if the customer still wants to pay.
</Note>

## You are done

That is the full integration. Register once, create invoices on demand, poll for confirmation. Everything else — credential security, LNbits communication, CORS — is handled for you.

Next: read the [Authentication](/authentication) page to understand how API keys work and how to handle them safely in your application.
